# Aqara 0.3.5 — Composite switch names and refresh feedback

Cloud composite switches now use the individual channel names configured in
Aqara Home. The endpoint-panel query includes the selected Cloud home and
account owner context; omitting that context could return an empty list and
leave only generic “Endpoint” labels. Endpoint IDs and advertised capabilities
continue to determine command targets.

Live read-only discovery of a four-button Z1 Pro returned four distinct names:
three relay channels with on/off support and a wireless button that remains
read-only. The fix uses shared endpoint metadata for all devices.

`aq up`, `aq upd`, and `aq update` keep **Refresh devices and scenes** first,
followed by workflow update. Learned result IDs are omitted from these choices
so Alfred cannot promote a previously selected upgrade above refresh. An
available-release row also stays below device refresh.

Refreshing now shows an immediate start notification. Reopen `aq upd` to see
progress; the results refresh automatically until completion. The refresh row
then shows the completion time and device/scene counts for that home. Failures
show a retry state, interrupted runs can be retried, and a running refresh is
not duplicated. Notification permission failures do not block catalog refresh.

Install [Aqara-0.3.5.alfredworkflow](https://github.com/schwark/alfred-aqara/releases/download/v0.3.5/Aqara-0.3.5.alfredworkflow)
or run `aq workflow:update` and confirm the upgrade in Alfred.

All 189 offline tests pass on Python 3.9 and 3.14. Validation covers named
composite channels, selected and linked home contexts, read-only wireless
buttons, refresh ordering, progress/completion, failures, stale selections,
and existing controls. Live checks used catalog and metadata reads.
