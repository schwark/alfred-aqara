# Aqara 0.3.2 — Automatic Cloud setup

On a new Mac, run `aq mode cloud` and `aq login`. The workflow now obtains the
shared app-signing configuration automatically; users no longer need to
download `const.py` or run `aq identity` before signing in.

- First Cloud use downloads a commit-pinned public GitHub reference, verifies
  its SHA-256 and size, and parses only the required literal constants without
  executing or retaining the downloaded Python source.
- Only the parsed app configuration and reference hash are cached in Keychain.
  Later uses need no GitHub request while that cache is valid. A replacement Mac
  recovers the shared values automatically from the same source, then you sign
  in again. Initial setup needs access to GitHub and the pinned reference.
- The GitHub request sends no Aqara account information, tokens, or signing
  headers. App values and personal credentials are excluded from the package
  and source. A corrupt cache is recovered automatically; changed upstream
  content fails verification. Existing advanced manual overrides still work.
- Lock transport is unchanged: Alfred uses Aqara's regional cloud API. The
  identity is not a lock-pairing key and adds no direct Bluetooth or LAN lock
  control. The tested U100 cloud route uses its M3.

Install [Aqara-0.3.2.alfredworkflow](https://github.com/schwark/alfred-aqara/releases/download/v0.3.2/Aqara-0.3.2.alfredworkflow)
or run `aq workflow:update` and confirm the upgrade in Alfred.

All 172 tests pass on Python 3.9 and 3.14, including fresh-machine login, offline
packaging, cache reuse and recovery, reference checksums and size limits, safe
network errors, account-data isolation, and advanced overrides. Both modes and
the Cloud-only device-list fix are preserved.
