# Aqara 0.3.6 — Clear account picker labels

`aq account` now puts the selected account first. Each entry uses its saved
account name as the title and identifies its role in the subtitle:

- **Work** — Current account · 1 home · Work Home
- **Personal** — Switch to this account · 2 homes · Main Home

Older connections saved with the placeholder name “Current account” use their
saved home label until renamed. Without a home, the neutral label is “Aqara
account.” Explicit account names are preserved. The picker reads local data
without accessing credentials, changing accounts, or contacting Aqara.

Account entries omit learned sorting IDs, and an available workflow update
appears below the picker. Home counts use “1 home” and “2 homes.” Both Agent
and Cloud modes use the same presentation, with profile IDs still determining
which account an action targets.

Install [Aqara-0.3.6.alfredworkflow](https://github.com/schwark/alfred-aqara/releases/download/v0.3.6/Aqara-0.3.6.alfredworkflow)
or run `aq workflow:update` and confirm the upgrade in Alfred.

All 196 offline tests pass on Python 3.9 and 3.14. New checks cover both modes,
legacy display labels, explicit-name preservation, correct account targets,
local-only browsing, and stable ordering with an available update.
